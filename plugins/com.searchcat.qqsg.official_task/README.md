# QQ三国官爵任务插件

## 使用前提

1. 角色已经取得官爵，并且当天尚未完成官爵任务。
2. 已导入当前游戏客户端数据，NPC 路由库中包含本国的奋威中郎将。
3. 游戏右侧任务追踪栏已经显示，并已校准 OCR 区域。
4. 已在地图调试中保存当前地图的地形模型，或准备使用任务栏 NPC 的游戏内置自动寻路。
5. 首次运行建议勾选“模拟运行”，确认窗口、截图和输入配置后再发送真实按键。

## 当前执行流程

1. 读取小地图名称和人物整数坐标，从人物实时位置规划到奋威中郎将。
2. 激活绑定窗口，按 G 后连续按 Enter 接取任务。
3. 点击场景退出可能残留的聊天输入模式。
4. 对任务栏截图执行原图、放大和黄色文字三轮 OCR。
5. 精确或模糊匹配 NPC；默认精准点击任务栏中的 NPC 名称，调用游戏内置自动寻路。
6. 监控小地图坐标，进入 NPC 半径 `1.5` 的邻域或确认游戏自动寻路停止后按 G 对话。
7. 继续读取任务栏，直到任务完成或达到配置的最大循环次数。

任务 NPC 优先使用游戏内置自动寻路，因为它能直接处理跳跃、斜坡和平台。地形规划用于首次前往任务发布人、地图调试以及任务栏点击不可用时的回退。

## 校准

配置中的坐标全部是游戏客户区坐标：

- `task_region`：右侧任务栏客户区区域 `[x, y, width, height]`。
- `minimap_region`：右上角地图名称和坐标的客户区 OCR 区域 `[x, y, width, height]`。
- 以上两个区域可直接使用脚本平台中的“框选任务栏”和“框选小地图”按钮设置，保存的是绑定窗口客户区相对坐标，窗口移动后仍可复用。
- `npc_routes`：导入的 NPC 位置，格式为名称到 `[地图ID, 小地图X, 小地图Y]`。
- `navigation_routes`：NPC 的定制路点；没有定制路点时仅使用 NPC 的终点坐标直线纠偏。
- `issuer_npc_name`：官爵任务发布 NPC，默认是“奋威中郎将”。插件会先寻路到这里再接任务。
- `accept_mode`：领取方式。默认 `enter_spam`，按 G 打开对话后连续按 Enter；
  `guided_click` 保留原来的模板/坐标逐项点击方式作为备用。
- `accept_enter_count` / `accept_enter_interval`：连续回车次数和间隔，默认 7 次、0.28 秒。
- `restore_control_click_point`：连续回车后用于退出输入模式的场景点击位置；留空时按窗口比例计算。
- `prefer_task_click_navigation`：默认 `true`，点击任务栏 NPC 名称调用游戏自动寻路。
- `task_cursor_park_point`：点击 NPC 后的鼠标停放位置；留空时自动移出任务栏，避免悬停改变下一次 OCR 图像。
- `npc_arrival_radius`：NPC 到达半径，默认 `1.5`。
- `near_npc_move_pulse`：接近 NPC 时的短距离点动时间，默认 `0.08` 秒。
- 三张识别模板依次对应按 G 后的“对话/任务”选项、具体官爵任务条目和“请交给我吧”。
  它们只用于领取官爵任务；到达任务 NPC 后的普通对话使用回车推进。
- `npc_interaction`：与 NPC 对话的方式；`keyboard_g` 表示按 G，`mouse_double_click` 表示双击。
- `npc_double_click_point`：使用双击方式时，NPC 所在的客户区坐标。
- `dialog_task_point`：按 G 后“对话/任务”选项的回退点击坐标。
- `task_entry_point`：任务列表中官爵任务条目的回退点击坐标。
- `accept_confirm_point`：“请交给我吧”的回退点击坐标。

在模拟模式观察日志，确认所有预计点击坐标正确后，将 `calibrated` 设置为 `true`。模拟模式不会发送真实键鼠输入。

插件会持续 OCR 小地图和任务栏。小地图整数坐标以所在坐标格中心参与地形吸附；最终接近 NPC 时按原始 NPC 坐标计算距离。斜坡行走允许 X、Y 同时变化，不要求高度完全相等。

自定义地形执行采用“输入一小段、松键、重新识别坐标”的闭环方式。跳跃会先尝试不按方向、只按空格；原地跳后坐标没有有效变化时，再按路线方向执行向前跳。下落会根据连接边方向走出平台，落点偏离后从实时坐标重新规划，不会沿旧方向无限重复。

## OCR 与 NPC 点击

任务栏 OCR 使用 PaddleOCR，并对同一截图执行三种处理：原图、三倍放大、黄色文字提取。`NPC` 被识别为 `IPC`、`1PC` 或 `lPC` 时仍可解析。

NPC 名称先与已采集路由库精确匹配；失败后使用多轮 OCR 候选进行模糊纠错。如果多个候选保留同一姓氏，且当前 NPC 库中该姓氏唯一，可自动纠正，例如 `霍楼/霍梭 → 霍峻`。候选不足以唯一确定时停止，避免误走。

点击位置不是整行文字中心。程序会根据 OCR 边界框计算 `NPC:` 后人名子串的中心，点击后将鼠标移到任务栏之外，再监控游戏自动寻路。运行日志会输出 OCR 原文、置信度、边界框、最终点击坐标和纠错理由。

定制路线示例：

```json
{
  "navigation_routes": {
    "奋威中郎将": {
      "map": "成都.子城",
      "waypoints": [
        [18, 15],
        {"x": 15, "y": 12, "jump": true},
        [11, 7]
      ]
    }
  }
}
```

每个路点都以小地图坐标表示。`jump: true` 表示该路点需要跳跃。路线执行中发生异常或用户停止插件时，平台会尝试释放所有仍按住的方向键。

## 可选模板

模板只用于备用的 `guided_click` 接任务方式。默认 `enter_spam` 模式会隐藏模板按钮，不需要配置。切换为模板方式后，可导入以下截图：

```text
dialog_task.png
task_entry.png
accept_confirm.png
```

模板模式默认在识别失败时停止。只有明确启用 `allow_coordinate_fallback` 后，才会回退到配置坐标。第一版不会自动判断角色是否被地图、战斗或其他弹窗阻挡。
## 游戏数据导入

在“自动化脚本平台”选中本插件后，点击“导入游戏数据”。程序会自动定位 QQ 三国安装目录，
只读解析 `data/objects.pkg` 内的 `res/Txt/MapData.txt`，使用当前客户端地图 ID 与插件坐标源合并，
并把结果写入插件配置的 `npc_routes` 和基础 `navigation_routes`。该过程不会解包全部资源，也不会修改游戏文件。
游戏寻路窗口中的 NPC 数据支持自动滚轮翻页采集，并按地图持久保存。新采集坐标优先于旧的网络或客户端导入坐标；已经采集的地图重启后可以直接复用，无需每次重新采集。

首批内置坐标覆盖蜀国官爵任务常见 NPC。未匹配地图和重名 NPC 不会静默选取错误路线，导入完成后会显示统计。
坐标源位于 `assets/data/npc_locations.json`，每项格式为：

```json
{"name": "奋威中郎将", "map": "成都.子城", "x": 11, "y": 7}
```

首批坐标依据 [巴哈姆特 QQ 三国蜀国 NPC 资料](https://wiki2.gamer.com.tw/wiki.php?n=36531%3A%E8%9C%80%E5%9C%8BNPC)
整理；地图 ID 始终以本机当前游戏包为准。
