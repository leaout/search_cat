# QQ 三国多窗口挖矿插件

插件提供：切换到14线 → 从江陵调用游戏代码寻路（或原动作路线）→ 配置巡逻并按G → 等待整点刷新。代码寻路当前未完成实机跨地图验证，不能视为全自动挖矿已跑通。脚本平台的“启动全部”会为每个已绑定窗口启动独立插件进程；生成链接的整段前台操作串行执行。

## 使用方式

1. 把需要挖矿的 QQ 三国窗口逐个绑定到脚本平台。
2. 将 `target_line` 保持为 `14`，并保持 `switch_line_enabled: true`。
3. 使用代码寻路时设置 `travel_mode: code`，目标907黄石矿洞二层，原始坐标1000,570（平台候选点，需实测）。先开启 `code_navigation_only: true` 单独调试；关闭模拟后才发送真实操作。默认保留 `travel_mode: actions` 和原 `travel_actions`，避免升级后改变旧路线。
4. 配置 `patrol_route`，例如四段移动：`[{"direction":"right","seconds":3,"g_count":1},{"direction":"left","seconds":6,"g_count":1}, ...]`。每段移动结束后插件会按 G。
5. 先勾选模拟运行测试换线、移动和按键顺序；确认无误后取消模拟运行并点击“启动全部”。

如果角色已经在矿区，可以把 `skip_travel` 设为 `true`。如果只想调试采集动作，可以只保留 `patrol_route`，先不执行跨地图路线。

换线提交后以窗口标题为成功依据；繁忙时关闭可识别提示并重试。`line_switch_max_attempts` 默认30，0持续尝试；`line_switch_retry_wait` 默认0.3秒。actions方式仍需配置路线；已在矿区可用 `skip_travel`。

脚本平台的“批量换线”运行时，按钮会变为“停止换线”；点击它或在脚本平台页面按 Home 可以停止。Ctrl+Shift+F12 为全局紧急停止。停止请求发出后，当前 OCR 调用返回即结束，后续点击、重试和其他窗口操作不再执行，日志显示“已停止”。状态栏区分“批量换线中”和“正在停止换线”。

选线界面优先使用普通 OCR；定位失败才进行黄色增强识别。已识别的行列用于推算固定两列、八行面板内缺失的线路（1–16 线）。面板几何信息不足时会再次识别，不会把“当前所在”底部说明、聊天文字或裸数字当作线路按钮。结果始终需要窗口标题确认。

识别到的目标数字也会与其他行的网格位置核对，避免把误读成目标线路的其他行直接点中。批量换线会处理线路或人数已满的提示；若窗口标题稍后才更新，下一次重试前会再次确认并结束操作。

`refresh_wait_enabled: true` 时，每轮巡逻完成后会等到下一个整点；如果不需要等待，可关闭它。`patrol_loops: 0` 表示持续巡逻，直到用户停止脚本。

插件仍保留了可选的 `template` 模式：将 `mining_mode` 改为 `template`，导入矿点模板后才会启用截图找矿。默认的 `patrol_g` 模式按照你描述的游戏机制直接走位并按 G，不依赖矿点模板。

## 当前边界

代码模式要求启动时确认江陵或目标地图；初始地图未知/不符不点击链接。链接点击成功不等于到达：两次实时OCR必须确认目标地图和坐标邻域，超时停止，不自动按方向键或G。跨地图是否可达、矿区等级及线路限制仍需游戏验证。巡逻默认仍未配置，不会猜测矿点路线。

完整命令及本地出口候选见 [代码寻路文档](../../docs/qqsg_code_navigation.md)。旧动作配置不会被删除；JSON和平台默认值均使用actions兼容，需手动选择code。

公开攻略多以“右键矿点”描述旧版本操作；你当前客户端是进入矿区后按 G 触发采集，所以默认按 G，模板右键模式仅保留作兼容调试。

# 矿锄管理：分步实施

选中挖矿插件后，界面提供“框选矿锄状态 / 框选背包物品 / 框选名称提示”。采集疲劳通过 F1 自动定位，无需框选。
先绑定并选中窗口，停止脚本/换线，在游戏里展示要框选的区域，再点击对应按钮。
名称提示按钮只配置可能出现提示的区域，不自动打开或悬停背包物品。
框选结果为客户区坐标，保存到当前插件配置；当前为共享配置，多窗口需相同布局。
若不同窗口分辨率或面板位置不同，应分别调整后单窗口调试，不能直接套用。

第三步（实验）已接通截图校准购买：活动快捷键 **I** → 兑换 → 商店物品 →
消耗品 → 经验&抗性 → 中级精钢矿锄 → 工资兑换 → 数量 1 → 确定。
启用 `pickaxe_auto_buy_enabled`，同时配置耐久监控和备用装备功能；默认关闭，不自动消费。
当前只支持原生像素比例的 Build36 布局，面板位置由至少两个 OCR 标签交叉确认，
按钮按面板内相对位置定位，面板移动不需要重新录入桌面坐标；缩放/布局不一致时停止购买。
提交前核对商品名称、5 工资、等级 70 和数量 1。
成交必须同时识别到新的成功弹窗（中级矿锄 1 个、失去工资 5）和工资余额恰好减少 5。
商店买到的是**道具包**：道具页使用并确认 → 装备页找到生成的矿锄 → 装备 → 读到正耐久。
付款成功只记为“已买、待使用/装备”，跨重启也阻止重复购买；正耐久确认后才完成补充记录。

自动购买暂限单窗口调试。`pickaxe_character_id` 必须是稳定且唯一的角色别名，
不用窗口标题/句柄，也不要填写密码；购买数据目录绑定角色别名，游戏重开后仍使用原流水。
`pickaxe_wage_budget` 默认 0，累计预算跨重启保留，不会启动一次就重新发放额度。
每次只买一把，点击最终确定前原子写入待确认流水；未确认到账的 pending 会阻止再次购买。
结果不明确时不重试消费，需人工核对；不要直接删除未知流水或同时开两套工具购买同一角色。
只有读到耗尽耐久，或此前明确读到不超过 5 耐久后矿锄连续消失，且背包确认无备用，才允许自动购买。

## 采集疲劳监控（F1 自动定位版）

用户新图为 `采集疲劳度334/2520`，代表已用 334、实际上限 2520、剩余 2186。
上限始终读取当前提示框分母，既支持此前的 2040，也不会把所有角色固定成 2520。
只接受有“采集疲劳度”标签的唯一合法分数，不将生命、体力、矿锄耐久当作疲劳。

默认启用 `fatigue_monitor_enabled`：自动检查状态面板是否已打开；未打开则按 F1。
通过“角色信息 / 角色抗性”两处一致的 OCR 锚点定位，按面板内相对位置悬停采集图标，
自动截取附近提示并读取分数，读取后核对并收起状态面板。面板移动不需要重新框选。
不将分辨率变化当作面板同比缩放；布局不一致、确认框遮挡、OCR 不完整或面板未收起时暂停，
按 `fatigue_recheck_seconds` 复查，不将未知当作 0。旧配置若明确保存为关闭，应在配置中启用此开关。
旧 `fatigue_region` 配置已不再使用；界面移除了疲劳框选按钮。
打开、悬停、截图、OCR 和收起作为一次宿主操作串行，避免多个窗口互相抢鼠标。
已实机确认 F1 打开/收起状态窗口；自动悬停读取及真实采集闭环仍需实机验证。

检查位于启动矿锄检查前、矿锄等待循环、移动片段、每次 G、模板点击、整点等待及补购前。
满额时结束本次插件，不再发送移动/采集/补购操作。
这不等于已取消游戏里正在进行的持续采集：取消操作未验证，需人工确认。
最新已用、上限、剩余、状态和观察时间保存到 `mining/fatigue-窗口标识.json`；重启重新读取，
不会凭旧记录假定还有额度，未知记录也保留为未知。
